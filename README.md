## 开始运行
1. 安装 Node.js 20+（本次 20.14.0）、Python 3.11+（仅重新生成初始素材时需要）。
2. 在项目根目录执行 `npm ci`，然后 `npm test`。构建会把 TS 编译到 `build/` 并复制 JS 到小程序目录，同时准备云函数依赖的共享算法。修改 TS 后必须重新 `npm run build`，不要直接改生成的 JS。
3. 微信开发者工具导入项目根目录 `D:\codex\pindou`；使用自己的 AppID，基础库选择当前稳定版本，最低按 3.7.7 配置测试。项目已填写用户提供的真实 AppID；云环境和广告位仍待配置。
4. 按下面完成云端与配置，再编译、真机预览。未配置时界面会提示暂不可用，不自动解锁。

## 云端部署
1. 创建 `patterns`、`unlocks`、`challenges` 集合。每个集合的自定义安全规则设置为 `cloudfunctions/database.rules.json`（客户端读写均 false），读写仅经云函数。测试别使用“所有用户可写”。
2. 图库查询按 status + _id 升序分页，尺寸筛选增加 width、height。按控制台提示建立组合索引：`status,width,height,_id` 与 `status,_id`。名称/关键词在 searchText 做字面正则搜索，查询最多 13 条、返回 12 条，不下发整库 cells。首次上架量适合 MVP，规模增加时另评估全文检索。
3. 云存储保持私有；api 云函数仅为本次列表中的已上架图纸封面生成临时读取链接。数据库仅管理员可读写，小程序通过云函数读取图库。封面是公开原创素材，不存用户原图。
4. `npm run build` 后，在微信工具右键 `cloudfunctions/api`，选择上传并部署并安装依赖。运行时选择当前受支持的 Node.js 18+，超时建议 15 秒。不要创建付费实例或未经确认升级套餐。
5. 为 unlocks 的 expiresAt、challenges 的 expiresAt 配置平台支持的 TTL 清理。资格本身不依赖 TTL 是否及时删除。若当前环境没有 TTL，每天由运营手动运行 `node scripts/cleanup.cjs` 清理过期记录；上线前明确责任人。

每日资格使用 `getWXContext().OPENID` 的散列键和服务端 `Date.now()` 计算北京时间自然日。事务写入 uid+日期文档，重复请求幂等；资格与生成页面内存资格相互独立。挑战绑定身份和用途，三分钟失效，仅接受明确的 isEnded=true。广告只采用客户端完整播放事件，**不提供服务端防作弊保证**，不冒充不存在的签名验证。详情结构化数据本来就免费可读，广告是应用内正常保存流程的商业规则，无法防止截屏或技术提取。当前官方服务端广告验证能力仍需拥有后台权限者复核，见 docs/platform-review.md。

## 实现细节与限制
- 新生成采用 96 色通用色表，P01～P96 为通用编号，非品牌型号。P01～P32 的数值保留，旧图库按 generic-32-v1 读取。区域 RGB 平均后转 OKLab；近中性灰（RGB 最大与最小通道差不超过 12）仅匹配黑白灰，其他颜色按颜色距离及低彩度过饱和惩罚选色；不改变色表，没有随机抖动或白底删除。
- 输入每次一张，选择压缩路径后再检查 10MB、1200 万像素和最长边 12000；超限清楚拒绝。支持可解码格式，EXIF 八方向归一化，工作画布最长边 1600。目标裁剪区域等比缩放至每格 4×4 的采样画布，再按区域平均映射；这是一种受控重采样，不承诺与原始全分辨率逐像素积分完全相同。
- 裁剪支持拖动与滑条缩放，不拉伸。原图、画布和生成图纸只在内存/平台临时目录，不写远程云端或用户长期文件目录。详情退出清理已知导出路径；选择器临时输入由微信临时文件机制回收。
- 完整 PNG 每格 28px，100×100 通常 2912px 宽；高度随统计增加。设备导出失败时最多按 50×50 分图，每张附全局坐标与整图统计。用户会看到张数提醒。分图中途保存失败后重试会重新保存全部分图，可能产生相册副本。
- 放大支持页面双指、拖动和全屏图片预览；预览关闭系统下载菜单，保存按钮执行资格检查。低内存设备降级分图。
- 生成广告只解锁本轮，选择取消和多次调整不会撤销资格；显式“开始新的一轮”重新看广告。不会跨会话/设备保留生成资格。
- 不提供离线模拟图库或广告成功。缺真实广告条件不能体验完整生成流程，仍可导入并免费浏览图库。
